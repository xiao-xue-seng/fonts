## 🟨Q：

ukai.ttc 中似乎有這幾個字型 AR PL UKai CN、AR PL UKai HK、AR PL UKai TW、AR PL UKai TW MBE。 但我不清楚他們在 .ttc 中的具體順序。如何整理出一個可供切片化的，包含簡體繁體的楷體字型檔。

---

## A：

這是一個非常核心且有趣的字型知識！

先為你帶來一個**極大的好消息**：

> 💡 **你完全不需要做「簡體與繁體的合併」！**
> 因為 `ukai.ttc` 裡的任何一個子字型（不論是 TW 還是 CN 版），**本身就已經同時包含「繁體字 ＋ 簡體字」了**！

以下為你詳細說明為什麼，以及如何用 Python 一鍵查詢子字型順序並匯出。

### 一、 釐清觀念：`CN`、`HK`、`TW` 的差異是什麼？

當年 Linux 開源社群（Debian/Ubuntu/飛火專案）在修復文鼎字型時，已經把文鼎原本的「繁體楷體」與「簡體楷體」**合併成了一個完整的 Unicode 大字庫**。

所以 `ukai.ttc` 裡面的子字型，差別**不是文字量不同**，而是**「同一個字的筆畫規範與標點符號位置」不同**：

| 子字型名稱              | 說明                                   | 標點符號位置 | 建議用途                        |
| :---------------------- | :------------------------------------- | :----------- | :------------------------------ |
| **`AR PL UKai TW`**     | **台灣教育部標準**（繁簡體字碼通包）   | **居中標點** | **最推薦！** 最適合繁體中文網站 |
| **`AR PL UKai CN`**     | **中國大陸 GB 標準**（繁簡體字碼通包） | 靠左下標點   | 適合簡體中文為主的網站          |
| **`AR PL UKai HK`**     | **香港常用字標準**（繁簡體字碼通包）   | 居中標點     | 適合香港標準繁體                |
| **`AR PL UKai TW MBE`** | 台灣教育部**筆順教學版**               | 居中標點     | 含筆順指示小點，適合教學使用    |

**結論：** 你只需要單獨把 **`AR PL UKai TW`** 抓出來，就能獲得一個**同時支援繁體 + 簡體，且標點符號預設居中**的完美楷體 `ukai-tw.ttf`！

### 二、 一鍵查詢順序 ＋ 自動匯出 Python 腳本

因為不同版本的 `ukai.ttc` 內部順序可能有些微差異，請建立一個 **`extract_ttcs.py`** 腳本，這隻腳本會自動掃描同目錄下的 **`ukai.ttc`** 與 **`uming.ttc`** 兩個檔案，自動辨識內部的子字型名稱，並一口氣幫你匯出以下 **4 個獨立的 `.ttf` 檔案**：

1. **`ukai-tw.ttf`**（文鼎楷體 - 台灣教育部標準，居中標點）
2. **`ukai-cn.ttf`**（文鼎楷體 - 大陸 GB 標準，靠下標點）
3. **`uming-tw.ttf`**（文鼎明體 - 台灣教育部標準，居中標點）
4. **`uming-cn.ttf`**（文鼎明體 - 大陸 GB 標準，靠下標點）

(詳見 tools/處理文鼎字型/extract_ttcs.py )

### 🚀 執行與後續切片指令

#### 步驟 1：執行 Python 腳本

```bash
python extract_ttcs.py
```

執行後，資料夾裡就會自動多出 `ukai-tw.ttf`、`ukai-cn.ttf`、`uming-tw.ttf` 與 `uming-cn.ttf`。

#### 步驟 2：分別進行切片 (分開輸出到子資料夾)

取得 4 個 `.ttf` 檔案後，你可以分別執行 `cn-font-split` 輸出到各自對應的目錄：

```bash
# 1. 切片 文鼎楷體 (台灣版)
npx cn-font-split -i ukai-tw.ttf -o ./ukai-tw

# 2. 切片 文鼎楷體 (大陸版)
npx cn-font-split -i ukai-cn.ttf -o ./ukai-cn

# 3. 切片 文鼎明體 (台灣版)
npx cn-font-split -i uming-tw.ttf -o ./uming-tw

# 4. 切片 文鼎明體 (大陸版)
npx cn-font-split -i uming-cn.ttf -o ./uming-cn
```

最後推送到 GitHub 倉庫，你的 CDN 倉庫就擁有完整涵蓋楷體與明體（含繁體居中標點/簡體靠下標點）的文鼎開源字型庫了！

## 🟨Q：

切片之後產生的result.css中會含有很長的完整的版權宣告，那不能移除，對嗎？

---

## A：

**是的，完全正確！絕對不能（也不建議）移除那段版權宣告。**

那段長長的版權宣告（CSS 註解文字 `/* ... */`）是 `cn-font-split` 工具在切片時，自動從字型檔案內部的 `name` 表格中提取出來並寫入的。

以下為你說明為什麼必須保留它，以及為什麼保留它完全不影響效能：

### 1. 法律與開源授權條款要求（Legal Requirement）

不論是 **SIL OFL 1.1**（如寒蟬、朱雀、芫荽體）還是 **ARPHICPL**（文鼎公眾授權），所有開源字型授權條款中都有最核心的一條：

> **「無論是原始版本還是修改後的版本（含格式轉換與切片），散布時均必須保留原作者的版權宣告（Copyright Notice）與授權說明。」**

`cn-font-split` 的作者非常有經驗，為了防止開發者在自託管時因為刪除版權宣告而意外侵權，所以強制把這段宣告自動貼在產出的 `result.css` 最上方。保留它能保證你的網站 **100% 合法合規**，免去侵權風險。

### 2. 對網站載入速度與流量「毫無影響」

你可能會擔心：「註解大約有幾十行，會不會增加流量負擔？」

**答案是：完全不會！**

1. **檔案極小：** 這段註解純文字大約只有 **0.5 KB ~ 1 KB**，跟一個 10MB 的字型比起來簡直微不足道。
2. **CDN 自動壓縮：** 當瀏覽器從 jsDelivr CDN 下載 `result.css` 時，CDN 會開啟 **Brotli / Gzip 傳輸壓縮**。因為這段註解是標準英文文字，壓縮率高達 90%，在傳輸時**實際上只佔用幾十個位元組（Bytes）**。
3. **瞬間下載：** 下載這段註解的時間不到 **0.0001 秒**，對網頁載入速度沒有任何可以感知的影響。

### 3. 對開源創作者的尊重

文鼎科技、寒蟬字型、璇璣造字、ButTaiwan 等創作者與社群，花費了數年時間免費開放這些高品質的中文字型給大眾免費商用，**保留這段版權註解是我們對開源創作者最基本的感謝與尊重**。

### 💡 總結

你只需要把 `cn-font-split` 產出的 `result.css` **原封不動**上傳到 GitHub 即可。你可以放心地保留那段註解，它既保護你不受法律追溯，又完全不會拖慢網站速度！
